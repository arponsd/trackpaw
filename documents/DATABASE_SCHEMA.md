# Database Schema

## Overview

Trackpaw uses three core tables and two optional tables. The schema is auto-created by the server package when `adapter.initialize()` is called. All adapters implement the same logical schema, with engine-specific optimizations (e.g., Postgres JSONB vs MySQL JSON vs ClickHouse nested columns).

## Core Tables

### `tp_events` — Event Log

The primary table. Every tracked action becomes a row here.

```sql
CREATE TABLE tp_events (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    event_name      VARCHAR(256) NOT NULL,
    user_id         VARCHAR(256),           -- NULL if not yet identified
    anonymous_id    VARCHAR(256) NOT NULL,   -- Always present (generated by tracker)
    session_id      VARCHAR(256) NOT NULL,
    properties      JSONB DEFAULT '{}',      -- Flexible key-value event data
    timestamp       TIMESTAMPTZ NOT NULL,    -- When the event occurred (client time)
    received_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(), -- When server received it
    ip_address      VARCHAR(45),            -- Stored only if IP tracking is enabled
    user_agent      TEXT,
    page_url        TEXT,
    page_title      VARCHAR(512),
    referrer        TEXT,
    device_type     VARCHAR(20),            -- 'desktop', 'mobile', 'tablet'
    browser         VARCHAR(100),
    os              VARCHAR(100),
    country         VARCHAR(2),             -- ISO country code (from IP, optional)

    -- Indexes (defined below)
    CONSTRAINT chk_event_name_length CHECK (char_length(event_name) <= 256)
);
```

**Indexes:**

```sql
CREATE INDEX idx_events_event_name ON tp_events (event_name);
CREATE INDEX idx_events_user_id ON tp_events (user_id);
CREATE INDEX idx_events_anonymous_id ON tp_events (anonymous_id);
CREATE INDEX idx_events_session_id ON tp_events (session_id);
CREATE INDEX idx_events_timestamp ON tp_events (timestamp);
CREATE INDEX idx_events_name_timestamp ON tp_events (event_name, timestamp);
CREATE INDEX idx_events_user_timestamp ON tp_events (user_id, timestamp);
```

**ClickHouse Variant:**

```sql
CREATE TABLE tp_events (
    id              UUID DEFAULT generateUUIDv4(),
    event_name      String,
    user_id         Nullable(String),
    anonymous_id    String,
    session_id      String,
    properties      String,  -- JSON string, parsed at query time
    timestamp       DateTime64(3, 'UTC'),
    received_at     DateTime64(3, 'UTC'),
    ip_address      Nullable(String),
    user_agent      Nullable(String),
    page_url        Nullable(String),
    page_title      Nullable(String),
    referrer        Nullable(String),
    device_type     Nullable(String),
    browser         Nullable(String),
    os              Nullable(String),
    country         Nullable(String)
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(timestamp)
ORDER BY (event_name, timestamp, user_id)
TTL timestamp + INTERVAL 365 DAY;  -- Configurable retention
```

### `tp_users` — User Profiles

Stores identified user profiles with their traits.

```sql
CREATE TABLE tp_users (
    user_id         VARCHAR(256) PRIMARY KEY,
    anonymous_ids   JSONB DEFAULT '[]',     -- Array of anonymous IDs linked to this user
    traits          JSONB DEFAULT '{}',     -- Custom user properties (name, email, plan, etc.)
    first_seen      TIMESTAMPTZ NOT NULL,
    last_seen       TIMESTAMPTZ NOT NULL,
    total_events    INTEGER DEFAULT 0,
    total_sessions  INTEGER DEFAULT 0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**Indexes:**

```sql
CREATE INDEX idx_users_first_seen ON tp_users (first_seen);
CREATE INDEX idx_users_last_seen ON tp_users (last_seen);
```

### `tp_sessions` — Session Records

Aggregated session data for session-level analytics.

```sql
CREATE TABLE tp_sessions (
    session_id      VARCHAR(256) PRIMARY KEY,
    user_id         VARCHAR(256),
    anonymous_id    VARCHAR(256) NOT NULL,
    started_at      TIMESTAMPTZ NOT NULL,
    ended_at        TIMESTAMPTZ,
    duration_ms     INTEGER DEFAULT 0,
    event_count     INTEGER DEFAULT 0,
    entry_page      TEXT,                   -- First page in session
    extp_page       TEXT,                   -- Last page in session
    referrer        TEXT,                   -- Session entry referrer
    device_type     VARCHAR(20),
    browser         VARCHAR(100),
    os              VARCHAR(100),
    country         VARCHAR(2),
    is_bounce       BOOLEAN DEFAULT FALSE,  -- Only 1 page view in session
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**Indexes:**

```sql
CREATE INDEX idx_sessions_user_id ON tp_sessions (user_id);
CREATE INDEX idx_sessions_anonymous_id ON tp_sessions (anonymous_id);
CREATE INDEX idx_sessions_started_at ON tp_sessions (started_at);
```

## Optional Tables

### `tp_event_definitions` — Event Catalog

For governance: stores known event names, descriptions, and expected properties.

```sql
CREATE TABLE tp_event_definitions (
    event_name      VARCHAR(256) PRIMARY KEY,
    display_name    VARCHAR(256),
    description     TEXT,
    category        VARCHAR(100),
    expected_properties JSONB DEFAULT '{}',  -- { "property_name": "type" }
    status          VARCHAR(20) DEFAULT 'active',  -- 'active', 'deprecated', 'hidden'
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### `tp_saved_queries` — Saved Reports

Stores dashboard report configurations for persistence.

```sql
CREATE TABLE tp_saved_queries (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(256) NOT NULL,
    description     TEXT,
    query_type      VARCHAR(50) NOT NULL,    -- 'trends', 'funnel', 'retention'
    query_config    JSONB NOT NULL,          -- The full query definition
    dashboard_id    VARCHAR(256),            -- Optional: belongs to a dashboard
    created_by      VARCHAR(256),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## Migration Strategy

### Auto-Migration on Boot

When `adapter.initialize()` is called, the adapter:

1. Checks if a `tp_migrations` table exists. If not, creates it.
2. Reads all applied migrations from `tp_migrations`.
3. Compares against the migration list bundled in the package.
4. Runs unapplied migrations in order.
5. Records each applied migration.

```sql
CREATE TABLE tp_migrations (
    id              SERIAL PRIMARY KEY,
    migration_name  VARCHAR(256) NOT NULL UNIQUE,
    applied_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Migration Naming Convention

```
001_create_events_table.sql
002_create_users_table.sql
003_create_sessions_table.sql
004_add_device_columns.sql
005_create_event_definitions.sql
006_create_saved_queries.sql
```

### Backward Compatibility

- Migrations only ADD columns or tables — never drop or rename.
- If a column needs renaming, create a new column + backfill migration + deprecate old.
- All new columns must have DEFAULT values or be nullable.

## Data Retention

Adapters support configurable data retention:

```typescript
const analytics = createAnalyticsServer({
  adapter: new PostgresAdapter({
    connectionString: process.env.DATABASE_URL,
    retention: {
      events: '365d',    // Delete events older than 365 days
      sessions: '365d',
      users: 'forever',  // Never delete user profiles
    },
    retentionCheckInterval: '24h', // Run cleanup daily
  }),
});
```

The adapter runs a periodic cleanup job that deletes rows older than the configured retention period.
